# Klubok — правила разработки

Этот файл — для агента, который **разрабатывает** Klubok.

- Продукт лежит в папке `vault/`: именно её получает пользователь.
- Инструкции в `vault/CLAUDE.md` адресованы агенту пользователя, а не тебе. Читай их как код продукта, а не как свою роль.
- План, решения и задачи — `docs/plan.md`. Критерии успеха v0.1 — `docs/criteria-v0.1.md`, они заморожены тегом `criteria-v0.1`.

## Жёсткие правила

- **Ничего личного.**
  - Не переносить в репозиторий личные записи — ни мейнтейнера, ни чьи-либо ещё. Все материалы пишутся заново, примеры — только про вымышленного «Сашу».
  - Перед пушем работает `scripts/privacy-scan.sh` (хук `.githooks/pre-push`). Стоп-лист лежит вне репо: `$KLUBOK_DENYLIST`, по умолчанию `~/.config/klubok/denylist.txt`.
  - Если проверка нашла совпадение, переписать текст. Хук не обходить.
- **Безопасность — блокер релиза.** Кризисный протокол, раздел «кому не подходит», честная рамка, сценарии.
- **Сначала сценарии, потом скиллы.**
  - Новое поведение агента начинается со сценария в `evals/scenarios/`.
  - Сценарии и критерии не ослабляются ради «зелёного»: если сценарий кажется неверным, сначала спросить мейнтейнера.
  - Скиллы пишутся по TDD: базовый прогон без скилла, потом скилл.
- **Клиническая точность.**
  - Сверять с первоисточниками (Beck Institute; Greenberger & Padesky; Burns).
  - Техники из ДБТ, CFT и майндфулнес помечать как заимствованные.
  - Защищённые материалы (листы Mind Over Mood, Stanley-Brown Safety Plan) не копировать, только пересказывать своими словами.
- **Слова.**
  - Процесс — «разбор», агент — «помощник по разбору мыслей».
  - Продукт не называть терапией. Не использовать «терапевт», «сессия», «специалист» (про агента), «лечит», «диагностирует», «клинически проверено». Дисклеймер «это не терапия» — можно.
- **Скиллы.** Имена папок латиницей `a-z0-9-`, во frontmatter только `name` и `description`.
- **Обновления.**
  - Upstream меняет в `vault/` только системное: `CLAUDE.md`, `.claude/`, `Reference/`, `Templates/`.
  - Пользовательские папки (`Journal/`, `Reviews/`, `Me/`) не трогать. `.obsidian/` после v0.1 тоже не трогать.

## Процесс

- Одна задача (issue T1–T10) — одна ветка от `dev`, затем PR и merge в `dev`.
- `main` — рабочая версия. Обновляется только PR `dev → main` на релизе, с тегом версии. Напрямую в `main` не коммитить.
- Заголовок коммита — по-английски, тело — по-русски. **Claude — соавтор каждого коммита:** последней строкой идёт трейлер `Co-Authored-By: Claude <noreply@anthropic.com>`. В `.claude/settings.json` он настроен так, чтобы добавляться автоматически.
- Тесты скриптов: `bash tests/privacy-scan.test.sh`.
- Репозиторий приватный до релиза v0.1. Сделать его публичным можно только после явного «да» мейнтейнера.
