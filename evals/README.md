# Прогоны сценариев

Здесь лежит всё, что нужно, чтобы прогнать сценарий из `scenarios/` на настоящем помощнике и оценить результат.

- `scenarios/` — сценарии, заморожены тегом `scenarios-v0.1`. Формат — в [scenarios/README.md](scenarios/README.md).
- `scenarios-heldout/` — скрытые варианты сценариев, результаты по ним разведочные. См. [scenarios/README.md](scenarios/README.md), раздел «Скрытые варианты».
- `run.sh` — раннер.
- `fixtures/` — исходное состояние vault для сценариев.
- `checklist.md` — как оценивать прогон вручную.
- `results/` — итоги прогонов, только синтетика.
- `tmp/` — сырые прогоны, в git не попадают.

## Запуск

```bash
evals/run.sh evals/scenarios/13-quick-abcde.md [out-dir]
```

Что делает раннер:

1. Копирует `vault/` во временную папку вне репозитория. Иначе помощник подхватил бы корневой `CLAUDE.md` с правилами разработки.
2. Накладывает поверх копии фикстуру сценария (см. ниже).
3. Подаёт реплики сценария по очереди через `claude -p`:
   - ход 1 — новый разговор;
   - следующие ходы — с `--continue`;
   - ход с пометкой «(новый разговор)» — без `--continue`, в той же копии vault.
4. Сохраняет ответы вместе с вызовами инструментов и снимок vault после последнего хода.

Реплики фиксированные: раннер не подстраивает их под ответы помощника.

**Прогон стоит денег.** Каждый ход — настоящий запрос к модели, сценарий — до 8 ходов. Тесты раннера (ниже) API не вызывают.

**Изоляция.** Прогон не должен зависеть от личной настройки Claude Code на машине мейнтейнера: глобального `~/.claude/CLAUDE.md`, скиллов, плагинов, хуков, автопамяти, MCP. Поэтому раннер вызывает `claude` так (массив `claude_flags` в начале `run.sh`):

- `--setting-sources project` — только настройки и `CLAUDE.md` самого vault, без пользовательских;
- `--settings '{"autoMemoryEnabled":false,"disableBundledSkills":true,"enabledPlugins":{"plugin-authoring@builtin":false}}'` — без автопамяти, встроенных скиллов и встроенного плагина `plugin-authoring` (см. ниже);
- `--strict-mcp-config` — без MCP-серверов и коннекторов claude.ai;
- `--tools Read,Write,Edit,Glob,Grep,Skill` — только файлы и скиллы, без Bash и веба;
- `--permission-mode acceptEdits` — запись в копию vault без запросов; запись за её пределы отклоняется.

Кроме того, раннер убирает переменные окружения родительского Claude Code, если запущен из него. `--bare`, `--restricted` и `CLAUDE_CONFIG_DIR` не подходят: первый и последний ломают вход по подписке, второй не грузит `CLAUDE.md` vault.

Как проверить: в `transcript.md` в начале каждого хода строка из init — модель, `session_id`, инструменты, скиллы. Там должны быть только скиллы vault (плюс служебные `design`, `doctor`, модели они не показываются). Если в init есть плагины или MCP-серверы, раннер останавливает прогон с пометкой «изоляция нарушена» и называет их.

**Встроенный плагин `plugin-authoring@builtin`.** CLI 2.1.272 включает его не во всех запусках: 2026-10-03 он появился в init у 6 прогонов из примерно 45, и эти прогоны остановились как недействительные. Доступность плагина решает флаг на стороне сервера, поэтому от запуска к запуску она меняется. Его скилл видит модель, значит, это настоящая утечка, а не шум.

- Раннер выключает плагин в `--settings` через `enabledPlugins`. Изоляция от этого только строже.
- Проверено 2026-10-04 на CLI 2.1.272. Переменная `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` включает плагин в каждом запуске: без настройки он есть в init, с настройкой его нет. Так же можно проверить новую версию CLI.
- Проверка init не ослаблена: если плагин всё же появился, прогон по-прежнему останавливается. Значит, настройка не сработала, и раннер нужно чинить.
- Повторять ход нельзя: он уже ушёл в модель и попал в историю `--continue`.

После прогона раннер удаляет временную копию и транскрипты прогона в `~/.claude/projects/`: они нужны только для `--continue`, а сырой вывод уже сохранён в `turns/`.

Коды выхода: 0 — все ходы прошли; 1 — ход не прошёл (claude упал, вернул ошибку в `result` или нарушена изоляция), следующие ходы не запускаются; 2 — ошибка входных данных, claude не вызывался. Нужен `jq`.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `KLUBOK_CLAUDE` | `claude` | какой бинарник вызывать; в тестах — заглушка |
| `KLUBOK_VAULT` | `vault/` | какую папку копировать |
| `KLUBOK_FIXTURES` | `evals/fixtures/` | где искать фикстуры и `map.txt` |
| `KLUBOK_EVAL_MODEL` | модель по умолчанию в CLI | модель для прогона (`--model`) |

**Модель (решение мейнтейнера, 2026-10-04).** Модель по умолчанию в CLI меняется от версии к версии, поэтому прогоны разных дней без закреплённой модели нельзя сравнивать.

- Подтверждающие прогоны: `KLUBOK_EVAL_MODEL=claude-sonnet-5-5`. CLI 2.1.272 этой модели не знает и пишет в stderr `unrecognized_model`, но отвечает именно она: проверено 2026-10-04 по `modelUsage` в `--output-format json`. Если с ней будут сбои — `claude-sonnet-5`, с пометкой в результатах.
- Один разведочный прогон кризисных сценариев: `KLUBOK_EVAL_MODEL=claude-opus-5-5`, чтобы понять, упираемся ли в модель. Его результаты подписываются как разведочные.
- В `meta.txt` две строки о модели: `модель:` — что запрошено, `модель в init:` — что CLI взял на самом деле (из init первого хода). Сравнивать можно только прогоны с одинаковой `модель в init`.

## Что получается

`out-dir` по умолчанию — `evals/tmp/<сценарий>/<YYYYmmdd-HHMMSS>/`:

```
evals/tmp/13-quick-abcde/20261003-141500/
├── turns/01.jsonl    ← сырой вывод хода 1, с вызовами инструментов
├── turns/02.jsonl
├── transcript.md     ← реплики и ответы по ходам, в читаемом виде
├── vault-after/      ← vault после последнего хода
├── meta.txt          ← сценарий, модель (запрошенная и из init первого хода), версия CLI, коммит, время
└── grading.md        ← заготовка оценки: пункты M/N сценария
```

`grading.md` заполняется вручную по [checklist.md](checklist.md).

## Фикстуры

Фикстура — папка в `fixtures/`, её содержимое копируется поверх копии `vault/` до первого хода. Так получается «Исходное состояние» из сценария.

| Фикстура | Что значит | Сценарии |
|---|---|---|
| `onboarded` | знакомство пройдено, страна — Россия; `Me/Как со мной работать.md` пустой | все, кроме 11 |
| `fresh` | знакомства не было: в `Me/` только `.gitkeep` | 11 |

- Какую фикстуру взять, раннер смотрит в `fixtures/map.txt`: строки `<сценарий без .md> <фикстура>`, `#` — комментарий. Если сценария там нет — `onboarded`.
- Формат `Me/Профиль.md` задаёт скилл знакомства (`vault/.claude/skills/onboarding/SKILL.md`). Фикстура `onboarded` ему соответствует: `onboarding: done`, `country: Россия`, `gender` пустой, без подробностей о человеке.
- В фикстурах — только то, что написано в «Исходном состоянии» сценария. Никаких выдуманных подробностей о человеке.

## Результаты

- `tmp/` в `.gitignore`. Там остаются сырые прогоны: их не коммитим.
- В `results/` попадают итоги (`results/v0.1.md`, формат — в [checklist.md](checklist.md)). Только синтетика: реплики из сценариев и ответы помощника на них. Никаких личных записей.
